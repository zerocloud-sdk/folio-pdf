# Program standards recorder qualification

The public `program-standards` command binds the fixed eight scopes, 42 predicates
and all 165 original controls. The initial missing-command RED preceded a full
actual PASS/42/165. Missing or substituted controls, profile, observer, qpdf pin
and fontTools wheel are rejected before they can supply rule coverage.

The producer receipt was first absent (actual Python CLI RED), then implemented
through stdout with a digest for every original output. qpdf writes to private,
bounded descriptors; those captured bytes supply both the program reader and
the published files. Java binds each report to that producer receipt and checks
the complete retained manifest. The receipt revision passed all 91 program and
structure tests, and the Java adapter's nine unavailable/changed-artifact controls
passed through two public tests. Its full normal observation retained 165
correctly detected controls. The mixed Maven run in which it passed also exposed
an unrelated declaration INDETERMINATE-publication regression; that historical
run is not presented as a passing whole suite.

Both independent reviews found one producer publication problem: Python could
overwrite existing files through symlinks or hardlinks, or publish through a
linked output directory. Java rejected many such observations afterwards, but
an existing qpdf.json hardlink could still lead to PASS/42/165 after its external
target was overwritten. Original review inputs and reports remain unchanged.
Actual public Python RED controls cover file symlinks, a hardlink, and output or
ancestor directory links. Exclusive file creation and checks before output path
resolution now refuse these writes; the three focused publication/receipt tests
pass. The full revised Python qualification passed 97 tests, including the
program, structure and qpdf identity suites. The Java declaration/program and
shared standards recorder regression passed 24 tests without skips.

The first closure reviews found one remaining Java failure-report path that
could create a directory and log beneath a replaced input ancestor. The public
JUnit control reproduced this separately (`ancestor-publication-red`), before
the fallback directory creation was removed and the shared exclusive writer
extended to check every ancestor. The focused regression then passed all 17
tests without skips, including the normal eight-scope, 42-rule, 165-control run.

Both independent axes closed this last correction. Standards retained ten
completed CLI observations: seven output-ownership controls, the complete normal
observation and two changed-artifact controls. Their original result data is in
`standards-ancestor-closure.tar.xz`. After an automated content flag interrupted
the review turns, closure continued by read-only source and existing-evidence
inspection; no further file-mutation probes ran. Spec independently checked the
normal run's 1,207 retained file identities, its exact rule/control sets and the
17-test log, without claiming a new CLI run. The final shared-helper snapshots
and the declaration regressions are retained by `recorder-r3`'s
`shared-helper-closure-archive-identities.json`.

`closure-archive-identities.json` binds the original failure, intermediate
reviews and final Java observations. Every archive member was read back and
compared with its original bytes. The completed Maven logs are retained under
their original names; mixed failing runs remain explicitly failing history.
This incremental closure does not cover the later combined or whole-corpus
aggregation commands.

These are qualification records, not final candidate or environment certification.
The retention recipe lists symlink targets instead of recreating absolute links,
rejects ELF/class redistribution, and reads back every archive member to compare
its bytes with the original. The original task directories remain available.
