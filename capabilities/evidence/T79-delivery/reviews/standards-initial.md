1. **Documented-standard breach — output stream declarations miss preflight.** `PdfBoxPasswordSecurity.PreparedOutput.preflight` checks only catalog Metadata, while `requireClearScope` runs only for an already-encrypted clear-scope Source. An unencrypted Source with contradictory ordinary-stream Crypt declarations can therefore reach caller work when clear-metadata output is selected. `docs/pdf-version-password-security.md:270` promises those declarations are rejected before caller work; ADR-0025 preserves operational failure/publication boundaries. Validate the requested output scope’s complete stream declarations during preflight, with a public regression that checks the callback is untouched and receipts are `NOT_ATTEMPTED`. Validate again after caller mutations before publication.

2. **Documented-standard breach — independent model confuses metadata roles.** In `build-tools/acceptance/arlington/t79-{input,output}.patch`, `Metadata.tsv`/`FilterMetadataCrypt` permits only Identity. Both upstream Catalog and PageObject link to that same model. Consequently protected component Metadata using StdCF is rejected, and component Identity receives the catalog-only dictionary exemption. This contradicts `docs/research/T79-clear-metadata-profile-audit.md` CM-CRYPT and its metadata-coverage table, and ADR-0023’s standards-evidence requirement. Separate the roles or use qualified context predicates; add positive and negative component overrides.

3. **Documented-standard breach — observer suppresses unknown warnings.** `scripts/t79-byte-check.py:130` maps every non-Perms authenticated pypdf diagnostic to `none`. `docs/t78-certification.md:102` states that no external warning becomes PASS; the reused baseline checker preserves an `other` category. Preserve a safe failing category for unexpected authenticated warnings and qualify its rejection.
