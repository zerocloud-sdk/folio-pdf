# T26 bounded table composition

Status: `experimental`
Capability: `composition.layout.tables`
Acceptance Profile: `T26-table-composition`
Release train: `0.1.0-SNAPSHOT`

T26 implements [issue 27](https://github.com/zerocloud-sdk/folio-pdf/issues/27)
through `DocumentWorkflow.execute`, using version-3 Paragraph Flow commands
and version-1 immutable Table/Row/Cell declarations. The
[English contract](../../docs/table-composition.md) defines width resolution,
complete span grids, inside-border geometry, finite limits and stable failure
behavior. Version 1/2 paragraph behavior is retained. The
[Chinese guide](../../docs/zh-CN/getting-started.md) includes usage and boundaries.

The independent oracle is
[T26TableExpectations](../../pdf-acceptance/src/main/java/net/zerocloud/pdf/acceptance/T26TableExpectations.java).
The three examples in the contract are translated by (52,580) onto 612x792-point
pages; font size remains 10. They cover FIXED columns [40,50,110], AUTO columns
[43,57] and the complete 2x3 span grid. Every scalar, baseline, advance, page box
and inside black border rectangle has an independent expectation with
0.0001-point tolerance. The reference PDF uses only T19 positioned text and
Canvas and never calls table composition. The semantic observer reopens
published PDFs through public queries. Negative controls apply five mutations
to each of the three pages (15 total): moving content, removing text, moving
borders, changing border color and removing the complete page content stream.

The three visual profiles pin 144 DPI, opaque-white sRGB, 1224x1584 pixels,
zero-fuzz ImageMagick AE 0 and a secondary changed-pixel ceiling of 2500. Their
expected rasters were generated from the hand-positioned reference before
rendering actual table products. Expected SHA-256 values are:

# Scope and verification

The shared public contract suite has 34 cases in each of IN_PROCESS and HARDENED_WORKER,
including exact table counts, layout-work and search boundaries, fractional
geometry, generated bytes, aggregate fonts, grid holes/overlap/overflow, atomic
area movement, query barriers, resource ownership, permissions, failure receipts,
Session expiry and sealing of previous buffered paragraph relayout.
It also covers mixed-flow failure attribution and AUTO's documented zero-column
rejection with surplus-width and explicit-column alternatives.

The [independent code reviews](T26-code-review.md) retain separate conclusions:
Standards passes with zero hard violations and two optional design judgments;
Spec passes after correcting the mixed-flow failure attribution finding.
These implementation reviews do not supply the separate standards/conformance
Acceptance Evidence chain.

The pre-implementation fixed point is
`aac85ebae1dfe89813a5f16b7fc236cdfc232c79`. At that point the requested minimum
baseline passed 187 tests locally on JDK 17; the two reported CI failures did
not reproduce. T26 does not modify those unrelated rendering or timeout paths.

No table splitting, repeated headers/footers, table keep, table relayout,
large-table flushing, new dependency or Migration Facade mapping is added.
The initial delivery was verified as an uncommitted working tree. The user
subsequently authorized a DCO-signed commit, a GitHub push and closure of #27
after repairing the failing GitHub Actions checks. This receipt records the
T26 verification before those separately scoped CI repairs.
