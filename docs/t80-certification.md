# T80 embedded-files-only password-security certification

The owned capability is `document.version-password-security.attachments`,
Foundation member `password-attachments`, profile `T32-password-embedded-files-only`.
The [source-traceable audit](research/T80-embedded-files-only-profile-audit.md)
and [English contract](pdf-version-password-security.md) own the declared behavior.
No current candidate claim comes from this prose: exact identities and actual
observations are bound exclusively by `capabilities/foundation-evidence.yaml`.

## Public behavior and original corpus

The independently authored corpus covers R4 RC4-128/AES-128, AES-256 R5/R6,
qualified PDF 1.7 extension declarations and PDF 2.0. It includes actual typed
and untyped EF streams, unrelated suggestive types, Identity defaults, EFF
StdCF/Identity/omission with explicit first Crypt selections, metadata flag/key
agreement, DocOpen/default and EFOpen events, empty/equal/Unicode/truncation
credentials, unrestricted users and malformed dictionaries/routes/Perms.
`cases.json` and `products.json` are the closed coverage authorities; neither
is supplied by a product or an observer. Manifest and pin changes require full
requalification. No iText implementation, fixture, resource or output is used.

Both public APIs emit and reopen actual randomized artifacts, with separate
Native-only RC4 output where the fixed Reference selector suppresses the requested
scope. Actual Source hashes/prefixes, COMMITTED publication receipts, scope and
crypto-mode observations and unauthenticated public-access results are retained.
New and replaced incremental attachments receive the preserved file protection,
including explicit Crypt when the original EFF is Identity. Facade runs
IN_PROCESS; Native selects IN_PROCESS or HARDENED_WORKER. Every tuple runs
sixteen Native tests, six Facade tests and two compiled artifact contracts.
They assert detached attachment bytes, credentials/permissions, PDF Value access,
protected donors/rewrite, signature restrictions, resource excesses/cleanup,
caller ownership and ordered preflight/partial-publication receipts.

## Four separate evidence chains

| Chain | Qualified original observations |
| --- | --- |
| Syntax | Pinned qpdf 12.4.0-folio-t80-r1 checks the original encrypted bytes. Its separately identified Apache-2.0 correction selects EFF through actual EF references and admits the optional scalar Crypt parameter Type. Exact credentials use a private hex-password file, removed after each invocation. Both the scope-specific and retained truncated-file controls must fail. |
| Standards | Pinned pypdf parses original plaintext encryption structures without attempting any password, including an empty one. Original adapters apply public dictionary/routing rules and report categorical findings. Applicable files also pass frozen Arlington 0.81 input/output predicates. Pinned pypdf/PyCryptodome independently prove exact credentials, owner authority and required Perms bytes. pdfcpu strictly validates the original clear page graph copied without authentication. Required dictionary, core and crypto defects must be detected. |
| Semantic | Original page streams, title and XMP are read through a parser whose encryption initialization is disabled before any credential channel exists. A separate authenticated parser supplies an object-specific independent EFF cryptor, selected by actual EF and explicit Crypt routes; decoded payload bytes must match the authored expectation. Independent qpdf graphs and literal public observations check versions, permissions, scope, mode and publication identity. |
| Visual | PDFium v0.11.2/chromium-7881 renders the unauthenticated clear page copy. ImageMagick 7.1.2-30 compares resource-free 144-dpi authored grids, annotations on, AE=0, zero fuzz. The original encrypted artifact hash binds each result. Changed paint and retained pixel controls must fail. |

The four chains exist for every required positive input and every emitted
Native/Facade product. A page derivative establishes only clear document/core
and visual properties; original dictionary, authentication, permission and exact
payload predicates separately establish encryption. The adapters import no
producer algorithms, product code or backend code. pypdf/PyCryptodome supplies
revision-specific cryptography; adapters route its existing cryptor and delegate
ordinary filter decoding. No generic-stream or suggestive-Type assumption proves
EFF coverage.

Two external-tool limits are explicitly qualified. The pinned Arlington engine
uses a PDFium parser that crashes on the profile's selective traditional-xref
inputs, R4 dictionaries with explicit byte Length, incremental trailers, and some
malformed selective dictionaries. The independent raw pypdf dictionary
adapter owns those original rules and its single-defect controls. Its qualification
cannot be manufactured by changing a label; live replay checks the original typed
values and exact pinned adapter. Compatible originals additionally pass Arlington.
The exact retained predicate decides this tool applicability. pdfcpu's encrypted
object-stream loader incorrectly decrypts Identity object streams for AESV2;
its T80 role is strict core validation of the unauthenticated clear graph, whose
fidelity is independently checked. Neither limit waives a required public success
or an evidence chain. Baseline T78/T79 observers, models and historical findings
retain their original meaning.

## Closed qualification and collection

Every scope control in `T80-controls/rules.json` and all retained T78 qualification
rules execute during recording and replay. This includes independent dictionary
types/lengths, reserved permission bits and Perms prefix bytes, unknown events,
EF/default/explicit routing, ordinary ciphertext, attachment plaintext, aliases,
invalid credentials, changed public modes and changed paint. Shared syntax,
strict-core, semantic and visual controls remain unchanged. Missing rules,
undetected controls, tools, chains, original artifacts or exact identities fail
closed. Authenticated parser warnings are failures.

The recorder binds corpus, original artifacts, source/contracts, compiled harness,
artifact bytes, JDK vendor/build/executable, immutable image, execution settings,
native installation, pinned tools, models and observer runtime. The collector
replays the actual external predicates against the retained randomized artifacts;
changed/resealed findings, declarations, modes or producer labels do not create
PASS. Reports omit credentials, keys, authentication entries and their hashes,
private paths, document contents and raw exceptions. Private credential/page
files are cleaned up on success or failure.

## Actual certification route

Supply the documented complete HarfBuzz and pinned Python installations, plus
pinned acceptance tools. Run the public and independent tests, full verification,
JDK matrix and collector rejection suite before freezing source/contracts/harness.

```sh
python3 scripts/provision-t80-qpdf.py
python3 scripts/provision-t80-arlington-model.py
python3 scripts/freeze-t80-inputs.py
python3 scripts/t03-foundation.py stage
python3 scripts/t03-foundation.py certify capabilities/evidence/foundation/T80-final/password-attachments --obligation password-attachments
./scripts/inventory generate
./scripts/inventory check
```

On that same unsigned candidate, refresh predecessor obligations first, in order:
transactions, values, pages, metadata, annotations, text, images, incremental,
password-baseline, password-clear-metadata, then password-attachments. Use fresh
sibling directories; never overwrite or relabel historical evidence. Any bound
source, contract, harness or artifact change requires restaging and fresh evidence.
The only eligible matrix is actual Ubuntu 24.04 Linux x86-64 × JDK 8/11/17/21,
with both Native profiles and actual Facade IN_PROCESS on each JDK. Windows
x86-64 and macOS x86-64/arm64 remain explicitly uncertified and nonblocking for
Foundation 0.1.0.

Aggregate `security` has exactly its existing baseline, clear-metadata and
attachment members. Its current completeness follows their dependencies and
candidate-bound receipts. Other Foundation obligations may still block release
readiness. This route grants no release publication, signing, push, PR or tracker
authorization. The delivery receipt is under `capabilities/evidence/T80-delivery/`.
