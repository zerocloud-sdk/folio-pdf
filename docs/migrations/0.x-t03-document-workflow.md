# 0.x migration: T03 Document Workflow

T03 makes Save Mode a caller-owned choice. The T01 one-argument request
factories selected rewrite publication implicitly and have been replaced by
factories that require an explicit mode:

```java
WorkflowRequest.create(path, SaveMode.REWRITE);
WorkflowRequest.open(path, SaveMode.REWRITE);
```

The equivalent Builder form is preferred when declaring named Sources or
Targets:

```java
WorkflowRequest.builder()
        .source("input", DocumentSource.path(path))
        .primarySource("input")
        .saveMode(SaveMode.REWRITE)
        .build();
```

This is an intentional source break during `0.x`, consistent with ADR-0012
and ADR-0013. `INCREMENTAL` remains an explicit vocabulary value but returns
the stable `SAVE_MODE_UNSUPPORTED` result until T15.

`PublicationReceipt.getTarget()` remains available for Path-only callers but
is deprecated. Code that handles both Path and stream Targets should use
`getPathTarget()` together with the receipt's request-local Target name and
status.

Deadline test clocks and other execution configuration belong to the
immutable Workflow Environment:

```java
WorkflowEnvironment environment = WorkflowEnvironment.withClock(clock);
DocumentWorkflow workflow = new DocumentWorkflow(environment);
```

Successful outcomes now also expose capability ID, execution profile, the
selected Save Mode, immutable safe diagnostics, and publication receipts.
