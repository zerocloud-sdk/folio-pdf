# 0.x migration: T03 Document Workflow

T03 makes Save Mode a caller-owned choice. The T01 one-argument request
factories selected rewrite publication implicitly and have been replaced by
factories that require an explicit mode:

```java
WorkflowRequest.create(path, SaveMode.REWRITE);
WorkflowRequest.open(path, SaveMode.REWRITE);
```

The equivalent Builder form is preferred when declaring named Sources or
Targets:

```java
WorkflowRequest.builder()
        .source("input", DocumentSource.path(path))
        .primarySource("input")
        .saveMode(SaveMode.REWRITE)
        .build();
```

This is an intentional source break during `0.x`, consistent with ADR-0012
and ADR-0013. `INCREMENTAL` now requires an existing primary Source and applies
T15's closed command classification and conservative Existing Signature policy;
requests without a Source fail with `INCREMENTAL_SOURCE_REQUIRED`.

`PublicationReceipt.getTarget()` remains available for Path-only callers but
is deprecated. Code that handles both Path and stream Targets should use
`getPathTarget()` together with the receipt's request-local Target name and
status.

Deadline test clocks and other execution configuration belong to the
immutable Workflow Environment:

```java
WorkflowEnvironment environment = WorkflowEnvironment.withClock(clock);
DocumentWorkflow workflow = new DocumentWorkflow(environment);
```

Successful outcomes now also expose capability ID, execution profile, the
selected Save Mode, immutable safe diagnostics, and publication receipts.


## T80 attachment-only password scope

`EMBEDDED_FILES_ONLY` now represents a supported Native encryption scope, with
Facade `EncryptionConstants.EMBEDDED_FILES_ONLY=24` and Folio alias
`ONLY_EMBEDDED_FILES`. AES selectors 26/27 are accepted; RC4 selectors 24/25
remain explicit safe rejections of contradictory Reference flag suppression.
Native RC4-128 V4 output is available with the existing legacy opt-in.

EFOpen readers can inspect ordinary clear content without a credential, while
attachment extraction requires explicit credentials and permission. An absent
credential differs from an explicit empty credential. DocOpen/default input still
requires document-open authentication. PDF Values and resource/copy paths cannot
bypass protected attachment access. Protected rewrites require owner authority
and an explicit output policy; new incremental attachments retain the original
protection. All-content AES-256 defaults, caller ownership, Existing Signature
rules and publication receipts are preserved. Consult the
[English contract](../pdf-version-password-security.md) and
[T80 qualification](../t80-certification.md) before relying on an interoperability
claim or certification tuple.
