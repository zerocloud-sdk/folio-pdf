# Proxy Document Sessions across the worker seam

`DocumentWorkflow.execute(request, work)` remains the Native Interface for both trusted in-process execution and the Hardened Worker Profile. The caller's callback always runs in the caller process against a Document Session: the in-process adapter executes project-defined Document Commands directly, while the IPC adapter selects one of two closed `executeBatch` transports. A fixed-size batch containing only blank-page insertion, page copy/move, or page removal is eligible for an encoded-length offer while its full modeled transport peak fits the parent's current message and aggregate owned-memory bounds. That peak is the larger of growable encoder capacity plus retained payload and simultaneous parent/child payload ownership plus the retained/received completion control. The batch crosses in one atomic frame only when the Worker accepts its complete payload allocation. Every other, parent-ineligible, or Worker-deferred batch uses one authenticated count declaration followed by Worker-driven indexed preflight, detail, and Command requests that acknowledge each predecessor. Both forms have one logical completion, and `execute` delegates its singleton batch through the same selection. Deferred per-Command encoding preserves the established stop-at-first-failure contract without consuming later one-shot inputs or allowing a later resource failure to replace an earlier semantic or backend failure. A Document Query is an ordering barrier that observes every earlier completed Command or batch prefix. The Worker accepts only versioned, whitelisted project values, Commands, and Queries—never lambdas, arbitrary classes, Java Serialization payloads, reflection targets, URIs, or user bytecode.

The T21 worker protocol is local-only, authenticated, versioned, length-bounded, and deadline-aware. Reference Font Set entries and explicit Font Sources remain parent-owned until selected by a command. The command carries opaque source identifiers; as the child evaluates them in declaration order, it requests each program and the parent applies the established limits before returning that program in a separate bounded frame. The child authenticates `STAGED` and `VALIDATED` progress back to the parent; listener delivery and the original environment Clock and deadline checks remain parent-owned and caller-thread-confined, while a monotonic watchdog supplies an independent hard Worker-lifetime ceiling. The Worker receives an inventory/hash-checked dependency-only runtime class path, not the application or test class path. T21 transports only values that fit one bounded message and completes final publication in the parent after a confirmed Worker exit. Idempotent transaction identities, large-value staging or chunking, lost-acknowledgement recovery, and uncertain-publication lookup are a distinct T22 extension; until then callers must not blindly retry an abnormal process loss. Remote worker networking is outside the Foundation Release.
