# Isolate worker data and secret material

Each Hardened Worker transaction uses a private, permission-restricted temporary root whose paths never derive from input names and which the parent removes after Worker termination; inability to remove that root prevents a successful outcome, and the project does not claim physical secure erasure on storage media. The primary Source is snapshotted before launch; other named Sources are requested, snapshotted, and classified one at a time in declaration order during Worker initialization, so an earlier failure cannot consume a later one-shot Source. Random product handles live in the same root, while reusable and explicit Font Sources stay parent-owned until selected. A selecting Command carries opaque identifiers, and the parent opens and returns each requested program in a separate bounded frame under the established limits. Workers are denied INET and Unix-domain networking, receive only an inventory/hash-checked dependency classpath closure, and cannot execute descendants. Remote Capability Providers are brokered explicitly by the parent, and sending document content remotely requires caller authorization. Passwords and private-key material use clearable arrays or provider handles rather than Strings. Initialization carries only security descriptors and credential-presence flags; credential characters stay parent-side until the child requests each required value in protocol order, and every credential transfer buffer is memory-accounted and cleared. Normal active-context failure envelopes are likewise accounted. Pre-context and post-context failures use a fixed eight-byte allowlisted descriptor bounded by the message limit because no transaction ledger is live; an exhausted or poisoned active context may use the same bounded codec to preserve its primary failure. Default logs exclude filenames, document content, metadata, credentials, private keys, and raw implementation exceptions.
