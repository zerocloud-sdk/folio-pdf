# Use a transactional Document Workflow

The Foundation Release Native Interface will center on a reusable `DocumentWorkflow.execute(request, work)` entry point that supplies a thread-confined Document Session with explicit page, layout, and content interfaces. The module owns opening, ordered changes, publication, cleanup, stable errors, and resource policy; it exposes neither backend types nor a generic capability service locator. Outputs are fully staged and validated before publication; each Path destination is committed atomically where the platform permits, stream failures may leave partial bytes, no cross-destination atomicity is promised, and a Publication Receipt records every destination. Callers explicitly select `REWRITE` or `INCREMENTAL`; signed files are read-only unless a permitted incremental change is requested. Convenience interfaces may be added as separate deep modules only after repeated caller needs demonstrate real leverage.
