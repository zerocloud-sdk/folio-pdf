# Retain idempotency state at the Workflow Environment boundary

An optional bounded non-secret Workflow Transaction Identity belongs to one logical Hardened Worker request and is retained in a finite, non-evicting, in-memory ledger owned by its Workflow Environment. Both record count and modeled metadata retained per record are bounded; an over-limit envelope is rejected before admission rather than retained partially. A cheap count check runs under the ledger monitor, while bounded request fingerprinting runs outside it. Byte Sources capture their content digest with their defensive declaration copy, so transaction admission does not rescan arbitrarily large content or serialize lookup behind that work.

The ledger binds the material request envelope, rejects concurrent, final, and mismatched submissions, and permits another attempt only from a recoverable state in which every target remains not attempted; caller work and mutable Path contents must retain the same meaning across that attempt, and the caller must restore the readable position of the same stream or channel Source. It records declaration-ordered Publication Receipts so a lost caller acknowledgement after all Path or stream targets commit resolves as completed, while any possibly partial stream output makes the transaction terminal and never replayable. This supplies process-local idempotency without a durable, cross-environment, distributed, automatic-retry, JVM-heap, or process-RSS claim.
