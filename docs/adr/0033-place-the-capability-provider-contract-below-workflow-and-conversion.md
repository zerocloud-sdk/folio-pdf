# Place the Capability Provider contract below Workflow and Conversion

The project-owned Capability Provider contract lives in a small `pdf-provider-contract` module that depends on no capability module; `pdf-document` consumes it so the immutable Workflow Environment can own registrations, while `pdf-conversion` consumes it to implement real adapters and remains free to depend on the Document Engine Native Interface for later conversion behavior. This preserves the ADR-0009 dependency direction for Conversion, prevents a `pdf-document`/`pdf-conversion` cycle, and keeps provider lookup out of the Document Session interface; the contract module must own real selection, limit, failure-normalization, and remote-disclosure behavior rather than becoming a placeholder interface artifact.

This is a staged foundation beneath ADR-0016, not an exception to it. T05 enforces detached request/result byte envelopes and the generic subprocess adapter's direct-child elapsed deadline, but issue #6 explicitly leaves comprehensive nesting, decompression, object/page/pixel, memory, temporary-storage, concurrency, and hostile-input controls to T20 and process-tree containment and hard isolation to T21. Until those gates are implemented, this experimental adapter is limited to trusted desktop and controlled batch workloads and does not satisfy ADR-0016's hostile multi-tenant policy.
