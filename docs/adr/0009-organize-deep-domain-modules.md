# Organize deep domain modules

The Maven reactor will be divided into deep modules around stable document capabilities rather than copying iText artifact boundaries or placing the entire suite in one jar. Its artifact families are `pdf-bom`, `pdf-document`, `pdf-composition`, `pdf-forms`, `pdf-trust`, `pdf-conformance`, `pdf-conversion`, `pdf-sanitization`, `pdf-migration-itext7`, `pdf-provider-*`, `pdf-acceptance`, and `pdf-testkit`. Capability modules may depend on the Document Engine Native Interface, Migration may depend on capability interfaces, and Provider adapters implement Conversion seams; capability dependency cycles are forbidden, and acceptance/test artifacts never enter production runtime. `pdf-document` remains one deep module with PDFBox hidden in its implementation: no public backend SPI or `api`/`impl` artifact split is created until a second real PDF backend exists. All first-party modules share one Release Train version managed by `pdf-bom` during `0.x`.
